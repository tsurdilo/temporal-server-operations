===================================================================
STATE MACHINE CONSTRAINTS
===================================================================

Valid Transitions:
- NORMAL → HANDOVER (via UpdateNamespaceRequest with state field set)
- HANDOVER → NORMAL (via workflow activity)

State-Specific Rules:
1. HANDOVER can only be set if:
   - Namespace is GLOBAL
   - Namespace has 2+ replication clusters
   - Namespace is in NORMAL state initially

2. While in HANDOVER:
   - Most WorkflowService RPC operations blocked (intercepted)
   - Cannot update namespace State (REGISTERED/DEPRECATED/DELETED)
   - Replication task execution is skipped on active cluster
   - HANDOVER state is NOT propagated to passive clusters
   - Clients receive Unavailable error or wait via interceptor

3. Exit HANDOVER:
   - Only via UpdateNamespaceRequest setting state back to NORMAL
   - Workflow activity performs this transition
   - Active cluster cluster can be switched during transition

Operational Semantics:
- Used for graceful failover/migration between clusters
- Prevents traffic during cluster handover
- Ensures remote cluster catches up before switching
- Rollback safety with timeout mechanism
